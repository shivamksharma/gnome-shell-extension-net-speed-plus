# Net Speed Plus

Real-time network download (↓) and upload (↑) speed indicator for the GNOME Shell top panel.

```
Activities        ↓ 2.5 MB/s  ↑ 128.3 KB/s        🔋  🔊
```

- UUID: `netspeed@shivamksharma.github.io`
- EGO: https://extensions.gnome.org/extension/9138/net-speed/
- Repository: https://github.com/shivamksharma/gnome-shell-extension-net-speed-plus

## Features

- Live download and upload speed in the panel.
- Automatic, KB/s-only, or MB/s-only unit formatting (with B/s and GB/s in
  automatic mode).
- Show download only, upload only, or both.
- Configurable update interval (0.5 s – 10 s).
- Active-interface detection from the kernel default route (`/proc/net/route`,
  `/proc/net/ipv6_route`), so Ethernet, Wi-Fi, mobile broadband, and VPN
  interfaces are all handled without a hardcoded interface list.
- Fully asynchronous I/O: no synchronous subprocesses or blocking file reads in
  the GNOME Shell process.
- Clean lifecycle: every timer, signal, and actor is released on `disable()`.

## Supported GNOME versions

The extension is built from one code base into two packages, because GNOME 45
changed the extension module system (legacy `imports.*` → ES modules):

| Package | GNOME Shell | Module system | Status |
| --- | --- | --- | --- |
| `scripts/build-legacy.sh` | 42, 43, 44 | legacy `imports.*` | 42 verified at runtime, 43–44 untested |
| `scripts/build-modern.sh` | 45–50 | ES modules | statically validated, runtime untested here |

GNOME 51 is expected to work but is not declared until it is released
(scheduled 2026-09-16).

See [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md) for the full, evidence-based
matrix. Untested versions are never claimed as verified.

## Architecture

```
extension.js / prefs.js      generated by the build (not committed)
src/
├── core/                    pure logic, no GNOME Shell or GI dependency
│   ├── constants.js
│   ├── formatter.js         unit formatting and display text
│   ├── procNetDev.js        /proc/net/dev parser
│   ├── route.js             /proc/net/route and /proc/net/ipv6_route parsers
│   ├── interfaceSelector.js active-interface selection
│   └── sampler.js           counter delta → bytes/second
├── shell/                   shared GNOME Shell / GIO layer (ES modules)
│   ├── procfs.js            async /proc readers
│   ├── networkMonitor.js    detection + sampling orchestration
│   └── indicator.js         PanelMenu.Button + label
├── modern/                  GNOME 45+ entry points (ES modules)
│   ├── extension.js
│   └── prefs.js
└── legacy/                  GNOME 42–44 entry points (legacy GJS)
    ├── extension.js
    └── prefs.js
schemas/                     shared GSettings schema
metadata/                    legacy metadata (modern metadata is metadata.json)
scripts/                     build, validation, transpiler
tests/                       unit and integration tests
docs/                        compatibility documentation
```

The `core/` and `shell/` modules are written once as ES modules. The legacy
build converts them to legacy GJS modules with `scripts/lib/esm2legacy.mjs`.
Only the entry points and preferences UI differ between generations.

## Installation

### From extensions.gnome.org

1. Visit https://extensions.gnome.org/extension/9138/net-speed/
2. Install and enable the extension.

### From a local package

```bash
./scripts/build-modern.sh          # or ./scripts/build-legacy.sh
gnome-extensions install --force dist/net-speed-plus-modern-v4.shell-extension.zip
```

Then log out and back in (or restart GNOME Shell) and enable the extension.

## Validation

```bash
./scripts/validate.sh
```

It checks metadata, UUID, the GSettings schema (strict compile), JavaScript
syntax, forbidden APIs (synchronous subprocesses, deprecated modules, private
Shell APIs, debug printing), transpiler output, import resolution, and package
contents.

## Network interface behavior

The monitored interface is the one the kernel selects for the default route:

1. Parse `/proc/net/route` (IPv4) and `/proc/net/ipv6_route` (IPv6) for default
   routes.
2. Choose the IPv4 default route interface (lowest metric), falling back to
   IPv6.
3. Ignore loopback (`lo`). No other interface name is blacklisted.
4. If the default interface disappears, or the `Gio.NetworkMonitor`
   `network-changed` signal fires, the interface is re-detected.
5. On any interface change the counter baseline is reset, so the first sample
   after the change reports zero instead of a bogus spike.

## VPN behavior

A VPN that takes over the default route (for example OpenVPN or WireGuard in
default-route mode) becomes the monitored interface, so the displayed speed is
the tunnel throughput. VPNs that use policy routing (`ip rule`/fwmark) keep the
physical default route; in that case the physical interface is shown and the
VPN is not counted separately. This is a deliberate, documented limitation of
reading the kernel routing tables.

## Unit behavior

- Units are binary: `1 KB/s = 1024 B/s`, `1 MB/s = 1024² B/s`,
  `1 GB/s = 1024³ B/s`.
- Automatic mode: `B/s` below 1024 B/s, then `KB/s`, `MB/s`, and `GB/s`.
- `KB/s only` and `MB/s only` keep a fixed unit.
- When both download and upload are hidden, the panel shows a single dash `—`.

## Preferences

- Update interval: 0.5, 1, 2, 5, or 10 seconds.
- Unit mode: automatic, KB/s only, MB/s only.
- Show download and show upload toggles.

Modern packages use `Adw.PreferencesPage` with `ExtensionPreferences`;
legacy packages use `Gtk.DropDown` widgets returned from `buildPrefsWidget()`.

## Known limitations

- Only IPv4/IPv6 default routes are consulted; policy-routed VPN traffic is
  attributed to the physical interface (see above).
- The modern (45–50) package has been statically validated and derives from the
  previously accepted GNOME 45–49 release, but it has not been executed on a
  GNOME 45+ session in this environment.
- Counter values are 32-bit on some kernels and can wrap; a wrap is treated as
  a reset and the sample is skipped.
